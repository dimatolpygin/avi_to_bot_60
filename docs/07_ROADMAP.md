**демонстрируемым результатом** (что можно потрогать руками). MVP-first: сначала
данные и ядро диалога на песочнице, транспорт Авито+amoCRM — в финале.

> **Прогресс всех этапов** — в [`STATUS.md`](STATUS.md). Внутри каждого этапа ниже —
> чекбоксы acceptance-пунктов. Закрытие этапа → git-тег `stage-N-done`.

## Этап 1 — Схема БД

**Цель**: полная схема прайса и промптов, на которую дальше садятся ETL, инструменты и панель. Проверяемо: таблицы созданы миграцией, сиды завели 3 аккаунта.

**Что делаем**:
- `src/db/schema.ts`: enum `account_kind` (goods/services), `availability` (in_stock/out/on_order/unknown), `price_unit` (piece/m2/linear_m/m3/set).
- Таблицы прайса: `accounts`, `categories` (дерево), `products` (article, name, grade, size, availability, stock_qty, note, is_active, `search_vector` для FTS), `product_prices` (несколько цен на позицию), `product_aliases` (синонимы для поиска).
- Таблицы промптов: `prompt_base` (общие правила), `account_prompts` (надстройка на аккаунт), `knowledge_blocks`, `faq`.
- Индексы: GIN по `search_vector`, trigram по `products.name` (pg_trgm).
- Сиды: 3 аккаунта (saunamart=goods, sbsauna=services, otdelka3=services/бюджет) + заглушка `prompt_base`.

**Критерии приёмки** (закрытие → tag `stage-1-done`):
- [ ] `npm run db:migrate` создаёт все таблицы и enum в БД `sbavito` без ошибок.
- [ ] В БД присутствуют enum-типы `account_kind`, `availability`, `price_unit` с нужными значениями.
- [ ] `npm run db:seed` заводит ровно 3 аккаунта; `SELECT code,kind FROM accounts` показывает saunamart/sbsauna/otdelka3.
- [ ] `availability` по умолчанию `unknown` (пустой остаток ≠ «нет») — проверяется дефолтом колонки.
- [ ] У `products` есть `search_vector` (tsvector) и GIN-индекс; повторный `db:seed` не плодит дубли аккаунтов.
- [ ] Схема сгенерирована в миграцию (`drizzle/*.sql`), а не только `push` — миграции версионируются.

## Этап 2 — ETL прайса

**Цель**: из 13-листового `Копия ИП Семенко ЕВ.xlsx` собрать один плоский прайс на каждый аккаунт, с нормализованными единицами и явным наличием. Механическая часть — Codex.

**Что делаем**: выбрать авторитетные листы, дедуп по артикулу/имени, разложить цены из текста характеристик, наличие из `остатки` (пусто→unknown), разнести по аккаунтам.

**Критерии приёмки** (закрытие → tag `stage-2-done`):
- [ ] Есть плоский файл прайса (CSV/JSON) на каждый аккаунт: `article, category, name, grade, size, unit, price, availability`.
- [ ] Отчёт: сколько позиций, сколько дублей схлопнуто, сколько пустых остатков (→ unknown).
- [ ] Спорные позиции из багов (необрезная, вагонка Экстра, осина Экстра) присутствуют с ценой и единицей.
- [ ] Файл выгружен клиенту на ревью актуальности.
