  (1) **аккаунтам услуг инструмент поиска не даётся вовсе** — прайса у них не существует,

  этапа 9 держит на диалог одну задачу и новое сообщение её ОТМЕНЯЕТ, а замок дал бы
  обратное — второй вопрос ждал бы, пока бот договорит ответ на первый;
  (3) **приветствие `/start` кладётся в историю руками**: оно уходит клиенту в обход
  модели, и без записи бот представляется второй раз на первый же вопрос;
  (4) **сбой Redis не роняет диалог** — ответить без памяти лучше, чем сказать
  «секунду, что-то подвисло»: моргание кеша не должно выглядеть поломкой бота.

  сроки, состав бригады и надбавку «процентов тридцать». Починено шестью коммитами:

  (4) **две реплики одной роли подряд склеиваются при записи**: ситуация штатная (клиент
  дописал, пока мы отвечали), но часть провайдеров падает на двух `user` подряд; по той же
  причине фолбэк «что-то подвисло» тоже идёт в историю;
  (5) **у окна склейки есть потолок от первого сообщения пачки**: ждать тишины после
  последнего мало, человек, который печатает без остановки, не дождётся ответа никогда;
  (6) **`Tempo` — объект, а не константы модуля**: только так тест и `probe --bystro`

## Протокол обновления

**При старте сессии**: прочитать этот файл → `git tag -l "stage-*"` (сверить с таблицей) →
`git log --oneline -10` → открыть `07_ROADMAP.md` на текущем этапе → только потом работать.

**При взятии этапа**: обновить «Текущий этап» + «Активная работа», статус 🚧,
коммит `chore(status): start stage N`.

**При закрытии**: все чекбоксы `[x]` и проверены человеком → `git tag stage-N-done` →
в таблице ✅ + тег + коммит (`git rev-parse --short HEAD`) + дата → запись в «Историю закрытий» →
коммит `chore(status): close stage N`.

**Если заблокирован**: статус ⏸ + в «Известные блокеры» что ждём и что нужно для разблокировки.
