у вагонки липа А L-3.0 цена за метр 171.00 против 285 в файле, у полка рабочая ширина пуста,

БД чистая — в ней только схема `sbavito`.

- **2026-07-22 — Этап 3: Схема БД + Alembic** — tag `stage-3-done` (`8655858`).
  11 таблиц и 5 enum в схеме `sbavito` (ревизия `7cac61ed44d2`), миграции применяет
  entrypoint контейнера до старта бота. Решения по прайсу зашиты в схему: `availability`
  по умолчанию `unknown`, `is_active` по умолчанию `true` (позиция не исчезает из каталога),
  уникальность `(account_id, article)` под идемпотентный импорт, `working_width_mm` nullable
  (у полка рабочей ширины не существует — пустое поле запрещает пересчёт в м²),
  `price_per_m` хранится вычисленной, редкие атрибуты печей и дверей — в JSONB `attrs`.
  Сиды завели 3 аккаунта и заглушку промпта, повторный прогон даёт 0 новых записей.
  Аннулированные таблицы Drizzle и схема `drizzle` вычищены из `public`
  (`scripts/ochistka_drizzle.sql`) — в БД осталась только схема `sbavito`.
  **Четыре грабли, все закрыты в коде и комментариях**:
  (1) `include_schemas=True` показывает автогену чужой `public`, и он предлагает удалить
  таблицы соседних проектов — фильтр `include_object` сравнивает имя схемы строго,
  потому что у отражённых объектов оно приходит `None`;
  (2) первый `upgrade` отчитался «Running upgrade», а база осталась пустой: `create schema`
  открывает транзакцию раньше Alembic, его коммит становится холостым — нужен явный
  `connection.commit()`;
  (3) триграммный индекс, записанный выражением `name gin_trgm_ops`, автоген сравнивать
  не умеет и молча пропускает — переведён на `postgresql_ops`;
  (4) Alembic создаёт enum при `create_table`, но не удаляет при `drop_table` — в `downgrade`
  дописан `drop type`, иначе повторный `upgrade` падает на «type already exists».
  **Проверено человеком** 22.07: лог «Применяю миграции» до старта; `bot.proverka` показал
  ревизию, 12 таблиц и 3 аккаунта; повторный сид — 0 новых; `downgrade -1` и `upgrade head`
  отработали подряд (после этого сид прогнан заново, аккаунты на месте). 15 тестов зелёные.

## Протокол обновления

**При старте сессии**: прочитать этот файл → `git tag -l "stage-*"` (сверить с таблицей) →
`git log --oneline -10` → открыть `07_ROADMAP.md` на текущем этапе → только потом работать.

**При взятии этапа**: обновить «Текущий этап» + «Активная работа», статус 🚧,
коммит `chore(status): start stage N`.

**При закрытии**: все чекбоксы `[x]` и проверены человеком → `git tag stage-N-done` →
в таблице ✅ + тег + коммит (`git rev-parse --short HEAD`) + дата → запись в «Историю закрытий» →
коммит `chore(status): close stage N`.

**Если заблокирован**: статус ⏸ + в «Известные блокеры» что ждём и что нужно для разблокировки.
